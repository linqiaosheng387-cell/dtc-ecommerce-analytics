## 🎓 技术深度展示（针对数据科学岗）

### 展示点 1：归因建模

**准备一张对比图**：
| 归因模型 | Google | Meta | TikTok | 业务决策 |
|---------|--------|------|--------|---------|
| Last-touch | $39.9K | $35.2K | $20.4K | 低估 Meta |
| First-touch | $56.1K | $53.0K | $31.8K | 高估拉新价值 |
| 时间衰减 | $52.3K | **$43.3K** | $28.4K | ✅ 推荐 |

**代码展示**（如果面试官感兴趣）：
```python
def time_decay_attribution(touchpoints, conversion_date, decay_rate=0.1):
    weights = []
    for tp in touchpoints:
        days_to_conversion = (conversion_date - tp.date).days
        weight = np.exp(-decay_rate * days_to_conversion)
        weights.append(weight)
    
    normalized_weights = weights / np.sum(weights)
    return normalized_weights
```

### 展示点 2：CLV 预测

**准备 BG/NBD 模型的直觉解释**：
- "用户有两个状态：活着（会继续购买）和死了（已流失）"
- "模型用历史购买频次和最近一次购买时间，预测用户当前是哪个状态"
- "预测未来 12 个月购买次数 = P(alive) × 预期购买频次"

**模型参数解释**：
- r, α：控制购买率的分布（r 越大，购买越集中）
- a, b：控制流失率的分布（b 越大，流失越缓慢）

**局限性（主动说明）**：
- ❌ 不适用于订阅制（需要留存曲线模型）
- ❌ 对新用户预测不准（数据太少）
- ❌ 假设客单价独立（实际高频用户可能客单价更低）

### 展示点 3：流失预警模型

**特征工程亮点**：
```python
# 示例特征：购买频次变化率
recent_30d_purchases = user_events[user_events.days_ago <= 30].shape[0]
historical_avg = user_events[user_events.days_ago > 30].shape[0] / 11  # 11个月均值
frequency_change_rate = (recent_30d_purchases - historical_avg) / historical_avg
```

**SHAP 可解释性**：
- 展示一个具体用户的 SHAP Force Plot（如果有时间准备）
- 或口头说明："模型告诉我们，这个用户流失的主要原因是 60 天未购买（贡献 +0.28）和邮件打开率下降（贡献 +0.09）"

**上线方案**（如果追问）：
1. 特征存储：Redis（实时）+ Hive（批处理）
2. 模型部署：FastAPI + Docker，实时推理 < 100ms
3. 监控：PSI（特征漂移）+ AUC（模型性能）+ 挽回率（业务指标）

## 🎯 面试常见追问 & 回答模板

### Q1: 如果预算只有当前的 50%，你怎么分配？

**回答框架**：
"我会用优化模型重新计算。假设总预算从 $4,425/天降至 $2,200/天："
1. 首先保证 Google 预算 $1,200（因为 ROAS 最高）
2. Meta 分配 $800（保持 Retargeting 能力）
3. TikTok 暂停投放（ROAS < 0.15 不值得投）
4. 剩余 $200 用于测试新渠道（如 Pinterest Ads）

"这样预测 ROAS 从 0.18 降至 0.16（下降 11%），但优于均匀削减（会降至 0.13）"

### Q2: CLV 模型有哪些局限？如何改进？

**回答框架**：
"BG/NBD 模型有三个主要局限："
1. **假设客单价独立**：实际高频用户客单价可能更低（需引入协变量）
2. **不考虑外部冲击**：如竞品降价、经济衰退（需加入时间序列成分）
3. **对新用户预测不准**：数据太少（需用相似用户的平均值）

"改进方向："
- 使用 **MBG/NBD**（带协变量的扩展版本）
- 结合 **留存曲线模型**（针对订阅制业务）
- 引入 **RNN/LSTM**（捕捉时序依赖）

### Q3: 流失预警模型如何解决样本不平衡？

**回答框架**：
"流失用户占比 35%，有一定不平衡但不严重。我采用了："
1. **类别权重调整**：LightGBM 的 `scale_pos_weight` 参数
2. **评估指标**：用 AUC 和 Precision@Top20%，不用 Accuracy
3. **阈值调整**：根据业务成本，设置最优阈值（不一定是 0.5）

"如果不平衡更严重（如 5%），会考虑："
- SMOTE 过采样
- Focal Loss（降低易分样本权重）
- 两阶段模型（先召回，再排序）
